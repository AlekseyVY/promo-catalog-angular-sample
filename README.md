# Каталог товаров и редактор промо-акций (Angular, фрагмент)

Фрагмент фронтенда на **Angular 17 + TypeScript (strict) + RxJS + NgRx ComponentStore**.

Код взят из коммерческого проекта (большие операторские таблицы и многосекционные формы) и обезличен:
- предметная область заменена на «каталог / промо-акции»;
- корпоративный UI-кит заменён на нативную вёрстку и Angular CDK;
- удалены названия, адреса стендов, ключи и персональные данные.

Архитектурные решения и код сервисов, стора, таблицы и хост-формы сохранены без упрощений.

## Что делает код

| Часть | Файлы | Что делает |
|---|---|---|
| Каталог | `ui/catalog-page` | Чипы-фильтры со счётчиками, быстрый поиск с debounce, клавиатурная навигация по чипам |
| Большая таблица | `ui/product-table` | Таблица на десятки тысяч строк: virtual scroll, OnPush, сортировка, выделение и навигация с клавиатуры |
| Состояние | `data-access/catalog.store.ts` | ComponentStore страницы: список, выбранная строка, фильтр, сортировка, фокус |
| API | `data-access/catalog-api.service.ts` | Типизированный REST-клиент: товары, справочники, акции, сохранение по разделам |
| Справочники | `dictionaries/dictionary-loading.ts` | Ленивая параллельная загрузка справочников по разделам формы, кэш, резолвер |
| Форма акции | `promo-editor/**` | Reactive Forms по разделам, кросс-полевые валидаторы, динамический FormArray, координатор сохранения |
| Маршруты | `app.config.ts`, `promo-catalog.routes.ts` | Lazy loading фичи и каждого экрана, `withComponentInputBinding` |
| Тест | `domain/product-type-filter.model.spec.ts` | Unit-тест логики фильтрации и счётчиков |

## Почему решения такие

**Таблица.** Операторы работают со списками в десятки тысяч строк, часто без мыши.
- `cdk-virtual-scroll`: в DOM только видимые строки.
- `ChangeDetectionStrategy.OnPush` и заранее посчитанные view-model строк (`IProductRowViewModel`). В шаблоне таблицы нет вызовов методов, и CD не пересчитывает скидку и статус на каждый тик.
- `Map<id, index>`: выделенная строка ищется за O(1), а не через `findIndex` на каждое обновление.
- `shareReplay({ refCount: true })`: одна подписка на расчёт списка для нескольких потребителей.
- UI-синхронизация через `requestAnimationFrame` вне зоны Angular (`runOutsideAngular`), без лишнего change detection.
- Навигация стрелками, PageUp/PageDown, Home/End и Enter. Таблица прокручивается, только если строка ушла из видимой области.

**Фильтры.** Логика фильтрации — чистые функции (`product-type-filter.model.ts`), без зависимостей от Angular. Их легко тестировать и переиспользовать.
- Счётчики всех чипов считаются за один проход по списку и не требуют отдельных запросов.
- Пересчёт идёт только по полному списку («Все»), иначе при выбранном фильтре счётчики обнулятся.
- Поиск не зависит от регистра и `ё/е`.
- Серверные фильтры (тип, сортировка, регион) уходят в API. Строка поиска ещё и сразу применяется на клиенте, поэтому пользователь видит результат до ответа сервера.

**RxJS.**
- `switchMap` в загрузке списка: новый запрос отменяет старый, ответы не перемешиваются при быстром наборе.
- `exhaustMap` в сохранении: повторный клик по «Сохранить» не создаёт дублей на бэкенде.
- `mergeMap(..., 3)` сохраняет разделы параллельно, но не больше трёх запросов сразу.
- `defer` создаёт запрос в момент подписки.
- Ошибки гасятся внутри внутренних потоков, чтобы не завершать внешний поток.
- Отписка через `takeUntilDestroyed`.

**Справочники.** Каждый раздел формы описывает свои справочники как `IDictionaryChunk` и регистрирует их через multi-provider `PROMO_DICTIONARY_CHUNK`.
- Новый раздел подключается одной строкой, загрузчик менять не нужно.
- Резолвер грузит всё параллельно (`forkJoin`) до открытия формы, поэтому форма не «прыгает».
- `DictionaryCacheService` кэширует справочники (`shareReplay`) и склеивает параллельные запросы. Ошибки в кэш не попадают.
- Падение одного справочника не ломает форму: пользователь увидит уведомление и пустой список.

**Форма.** Разделы — независимые standalone-компоненты со своими `FormGroup` и `FormArray`. Они регистрируются в `HostFormService` (provided на уровне редактора).
- Хост видит общую валидность и сохраняет только изменённые разделы.
- Разделы не знают друг о друге, поэтому раскладку можно менять: вкладки, единый скролл, режим чтения.
- Валидаторы кросс-полевые и вешаются на группу: диапазон дат, значение скидки по механике, уникальность товаров в `FormArray`.
- Сообщения об ошибках собраны в одном словаре.
- Формы строго типизированы (`nonNullable`, `FormControl<number | null>`).

**Lazy loading.** Фича грузится через `loadChildren`, каждый экран — через `loadComponent`. Провайдеры справочников живут только внутри фичи, а `CatalogStore` — только на странице каталога.

## Проверка

```bash
npm i
npm i -D @angular/compiler@17.3 @angular/compiler-cli@17.3
npx ngc -p tsconfig.json --noEmit
```

Код компилируется без ошибок в режиме `strict` + `strictTemplates`. Unit-тест фильтров проходит (3/3).

Это фрагмент, а не готовое приложение. Здесь нет bootstrap, тостера уведомлений и бэкенда.
